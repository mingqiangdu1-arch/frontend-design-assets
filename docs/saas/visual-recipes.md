# SaaS 视觉规则 · Refined Light 系列的具体用法

状态：**设计提案 / 专题补充**。沿用 [DT-001 主题](../../styles/refined-light-saas/README.md)，不是整个仓库的默认 UI。

## 视觉信息层级

### 横向布局

- 第一层：240px 左导航；56px 顶部工具行；主内容留白 28–32px。
- 第二层：页面标题、简短描述、唯一主要操作。
- 第三层：紧凑工具栏（搜索、视图筛选、显示密度、更多操作）。
- 第四层：大面积表格/数据区。表格尽量使用横线和浅色 hover，不增加纵向格栅和多层嵌套卡片。
- 第五层：关联详情作为右侧 Sheet，用户完成后能返回原列表位置。

### 组件基线

| 元素 | 建议值 | 注意 |
| --- | --- | --- |
| 侧栏 | 240px，背景 #F7F7F8 | 默认与内容区 1px 分割 |
| 顶栏 | 56px 白底 | 标题辅助信息不争夺注意力 |
| 页面标题 | 24/32px，600 | 不把所有 section 做成大标题 |
| 表格正文 | 13–14px / 20–22px | 行高舒适 48px，紧凑 36–40px |
| 搜索框 | 36px，边框 #D4D4D4 | Ctrl+K 是全局搜索，不占用页内搜索 |
| 主操作 | 36px，#171717 填充 | 每个视图只保留一个主 CTA |
| 状态标签 | 6px 圆角、低饱和底色 | 同时有文字，不能只靠颜色 |
| Inspector | 400–480px 参考范围 | 小屏改为宽度适配/独立页面 |
| 动效 | 120–220ms | 减少动画偏好或高频场景适当取消 |

色彩值是**自定义提案**，不是 Attio/Vercel 官方 Token。

## 具体组件建议

### 列表和表格

表头强调维度而非边界线。可排序列提供**可感知的排序方向**和明确按钮；数字使用 tabular nums。行首实体是明确可点击链接/按钮。批量选择出现上下文操作栏，避免整表过多永久按钮。

### 视图与过滤

视图切换不应该在用户未知的情况下保存到团队共享范围。区分“临时筛选”、“个人保存”、“工作区共享”。本轮演示仅临时视图，暂未实现持久化 Saved Views。

### Sheet 与菜单

Sheet 用于阅读关联详情、就地简单编辑。Modal 仅用于阻塞性确认。菜单使用点击而非纯 hover 打开；权限不足的动作不应偷偷提供可点击后失败的入口。

### 空态与加载

Loading 占位必须匹配目标内容尺寸；空态区分“没有记录”和“筛选无匹配”，后者应提供清除筛选入口；错误需要 Retry，而不是只显示错误图标。

## 视觉风格质量检查

- 1440px 和 390px 均不产生水平溢出。
- 表格在窄屏必要时容器内横向滚动，不牺牲列可读性。
- 选中态、悬停态、焦点态彼此可区分。
- 页面只有一套 Token / 图标笔画体系，不从外部案例复制品牌标识。
- 禁止巨大圆角、模糊玻璃、紫蓝发光、过度卡片化。
